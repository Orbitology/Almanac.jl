Ephemeris and rotation tables

An inner loop or a GPU kernel that needs the position of a body many times over a known interval does not have to touch the kernels. ephemeris_table extracts the position into an EphemerisTable: one flat array of Chebyshev coefficients on equal intervals, evaluated without loaded kernels, segment search or chain of bodies.

Build and evaluate an ephemeris table

using Almanac

t0 = str2et("2025 MAR 01 12:00:00 UTC")
t1 = t0 + 86400.0
tab = ephemeris_table("PROBE", t0, t1, "J2000", "NONE", "EARTH"; tol=1e-6)
(tab.nint, tab.ncoef, tab.maxerr)           # intervals, coefficients per interval, measured error (km)
(128, 16, 5.863420009621963e-11)

tol is the accepted error in km; its default is 1e-12 times the largest distance in the table. table_position, table_state and table_jet return the position, the state, and the position with its derivatives of any order.

Epochs can be ForwardDiff.Dual numbers, also on the GPU.

An epoch outside the table throws SpiceError(:spkinsuffdata), not the SpkInsufficientDataError of spkezr. This check is a bounds check: @inbounds removes it, as GPU code requires, and an epoch outside the table then extrapolates the nearest interval.

How the table is built

For a geometric position in an inertial frame from SPK type 2 data, as in the planetary ephemerides, the table copies the records of the kernel and agrees with spkpos to rounding. Otherwise (a rotating frame, an aberration correction, other SPK types) it interpolates, doubling the number of intervals until the measured error is below tol, and maxerr records that error. ephemeris_table gives the exact conditions.

The velocity of a table is always the derivative of its position, so it can differ from the velocity of spkezr with an LT correction, or for SPK types that store the velocity separately.

Rotation tables

rotation_table does for pxform what ephemeris_table does for spkpos, by interpolating the nine elements of the matrix. table_rotation returns the matrix, and table_rotation_jet the matrix and its derivatives.

rtab = rotation_table("J2000", "IAU_EARTH", t0, t1)
maximum(abs, table_rotation(rtab, et) - pxform("J2000", "IAU_EARTH", et))
4.751740667607862e-12

The matrix is not orthogonalized again, so its distance from orthogonality is of the order of the error of the table. The errors below are Frobenius norms over six days from 2022-03-08, with the default arguments:

Save a table as a kernel

table_to_spk writes a geometric table to an SPK file as one segment of type 2. The spkezr of Almanac.jl or of CSPICE then returns the state of the table to rounding: 2e-16 relative, measured for the Moon seen from the Earth over 200 days.

path = joinpath(mktempdir(), "table.bsp")
handle = spkopn(path, "from a table", 0)
table_to_spk(handle, tab, "PROBE from a table")
spkcls(handle)
spkobj(path)
1-element Vector{Int64}:
 -999

Evaluate on a GPU

The table is parametric in its array type, so Adapt.jl moves it to a device, and its evaluation is plain arithmetic that compiles in a GPU kernel. Epochs and bounds stay Float64 even with Float32 coefficients, because a Float32 count of seconds past J2000 resolves only about a minute. Below, epochs is a vector of Float64.

using CUDA, Adapt

gpu = adapt(CuArray, tab)                   # `cu(tab)` gives Float32 coefficients
states = map(et -> @inbounds(table_state(gpu, et)), CuArray(epochs))

Use a table in a CasADi model

CasADiCodegen.jl generates Julia code from a CasADi model; its callback embeds a Julia function with the derivatives CasADi needs. Since table_jet returns static vectors, a table gives the position of a body to generated code without allocation, and its derivatives to the Jacobian. A sketch (not a complete program) for an Earth satellite perturbed by the Moon, where t0, t1, GM_EARTH and GM_MOON come from the application:

using Almanac, CasADiCodegen, LinearAlgebra

tab = ephemeris_table("MOON", t0, t1, "J2000", "NONE", "EARTH")
order(k) = let v = Val(k); t -> table_jet(tab, t[1], v)[k+1]; end       # derivative k of the position
moon = callback(order(0), "moon", (1,), (3,); jacobian = (order(1), order(2)))

x, t = MX.sym("x", 6), MX.sym("t")
r, s = x[1:3], moon(t)
a = -GM_EARTH * r / norm(r)^3 + GM_MOON * ((s - r) / norm(s - r)^3 - s / norm(s)^3)
z = vertcat(x, t)
f = CasADiCodegen.Function("f", [x, t], [vertcat(x[4:6], a), jacobian(vertcat(x[4:6], a), z)])
g, g! = build_function(f; expression = Val{false})

t is in seconds past J2000 TDB and order(k) returns the k-th derivative in km/sᵏ; CasADi takes first derivatives from order(1) and second from order(2).
