Contexts and threads

Every call that reads kernels takes an optional SpiceContext as its first argument (Conventions gives the rule). Pure functions such as vnorm take no context. A program with one set of kernels never needs to name a context; this page is for programs with several sets, or with several threads.

One context per kernel set

Contexts are independent of each other. Use one per version of an ephemeris, or one per mission. Here kernels holds the paths of the example kernels, written as in Getting started:

using Almanac

kernels = DocKernels.write(mktempdir())
mission = SpiceContext()
foreach(k -> furnsh(mission, k), kernels)

(ktotal(mission, "ALL"), ktotal("ALL"))     # the default context is still empty
(3, 0)

Query from many threads

A query reads an immutable snapshot of the context and takes no lock, so any number of threads can query one context at once:

et = str2et(mission, "2025 MAR 01 12:00:00 UTC")
epochs = et .+ range(0, 86400; length=10_000)
distance = Vector{Float64}(undef, length(epochs))

Threads.@threads for i in eachindex(epochs)
    position, _ = spkpos(mission, "PROBE", epochs[i], "J2000", "LT+S", "EARTH")
    distance[i] = vnorm(position)
end

extrema(distance)                           # km
(7077.737331854382, 42166.5247735826)

furnsh, unload and the calls that change the pool (pdpool, ldpool, ...) may run while other threads query. Each of them builds a new snapshot and swaps it in atomically, so a query sees the kernels before or after the change, never a mixture. Concurrent changes are serialized. A change can land between two consecutive queries, so they can see different kernels.

Prepare a query for many epochs

state_query and rotation_query resolve the names, the frame and the correction once, on the current snapshot. Evaluating the query, as q(t) for the state or spkpos(q, t) for the position, gives the result of spkezr or spkpos bit for bit; a rotation query gives that of pxform. The query skips the name lookup at each epoch, and keeps its snapshot even if another thread loads a kernel.

q = state_query(mission, "PROBE", "J2000", "LT+S", "EARTH")

positions = [spkpos(q, t)[1] for t in epochs]
q(epochs[1]) == spkezr(mission, "PROBE", epochs[1], "J2000", "LT+S", "EARTH")
true

To see kernels loaded later, make a new query.

What threads can share

A file handle (from dafopr, dasopr, spkopn, ...) and a Window that is being changed must not be used from two threads at once. Queries (StateQuery, RotationQuery) and tables (EphemerisTable, RotationTable) are immutable, and safe to share.
