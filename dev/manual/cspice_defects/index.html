Defects of CSPICE N0067

Almanac.jl takes CSPICE N0067 as the reference for its results. Where CSPICE has a defect, Almanac.jl either copies it, so that its results equal those of CSPICE, or fixes it, so that its results differ for the inputs that the defect concerns. This page lists the defects known to the maintainers in the routines that Almanac.jl ports, and what Almanac.jl does about each.

The defects come from the tests of Almanac.jl, from NAIF's test suite replayed against Almanac.jl, and from the list of SPICELIB bugs of PEPPER, a Fortran port of SPICELIB. Not listed: defects of routines that Almanac.jl does not port, and defects of the Fortran source that cannot occur in Julia, such as a string passed as both input and output.

How to read the tables:

  • Where names the routine of SPICELIB in lower case, _c for a routine written in C. Parentheses name the public calls through which the defect shows.
  • Test names the test group (test/test_<group>.jl) that covers the behaviour.

Most fixes replace a crash, a read of undefined memory or an endless loop with an error or the correct result.

Fixes that change no computed value

  • scs2e, wninsd, wncomd, lstcld, lxqstr, zzrvar: a test that does not short-circuit reads one element past the end.
  • Slow: namfrm never hits its cache; ccifrm examines each name up to 100 times.
  • stmp03: SPICELIB built with Intel Fortran on Windows sums 10 terms; CSPICE and Almanac.jl sum 11.
  • zzekjtst: the element indices of a non-key join constraint are never set. Only a non-scalar column reaches them, which the copied zzeksemc defect allows; Almanac.jl compares element 1 there, as in the copied row.
  • zzekad06: a message prints the record count as the range of column indices; the check cannot fail through a public call.
