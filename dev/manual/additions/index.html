What Almanac.jl adds

These features have no counterpart in CSPICE:

  • Derivatives of any order of states and rotations: spkder, pxder. See Time derivatives.
  • Automatic differentiation through ForwardDiff.jl (dual-number epochs) and through Enzyme.jl, Mooncake.jl, Zygote.jl, ReverseDiff.jl and Tracker.jl (other AD packages).
  • Queries resolved once, for many epochs: state_query, rotation_query. See Contexts and threads.
  • An aberration correction parsed once: Aberration. After ab = Aberration("LT+S"), write spkezr("MOON", et, "J2000", ab, "EARTH").
  • Tables for inner loops and GPUs: ephemeris_table, rotation_table. See Ephemeris and rotation tables.
  • Bodies and frames defined by Julia functions: add_ephemeris!, add_frame!. See Bodies and frames from your own functions.
  • Orbital elements, two-body propagation and relative motion: Orbit. See Orbits and relative motion.
  • Kernels built in memory, with no file: load_samples!, load_function!, and spkops, ckops, pckops with furnsh of the handle. See Load states as a kernel, with no file.
  • Scratch files kept in memory: dasops, ekops. CSPICE writes a temporary file instead.
  • Text kernels in JSON, described below.

Text kernels in JSON

A file named *.json is read as a text kernel written as one JSON object, in the format of jsonspice, which PEPPER also reads. furnsh, ldpool, unload, kinfo and meta-kernels accept it; CSPICE does not. The extension decides the format: a JSON file with another extension is read as a classic text kernel, and loads nothing, because it has no \begindata.

// earth.json
{
    "BODY399_RADII": [6378.1366, 6378.1366, 6356.7519],
    "+NAIF_BODY_NAME": "SPOCK",
    "+NAIF_BODY_CODE": -1000,
    "EPOCH": "@2026-NOV-11/12:00",
}
  • Each member is one assignment. A key "+NAME" appends to the variable, like +=.
  • Numbers, true (1) and false (0) are numeric values. Strings are string values, and a string that starts with @ is a time.
  • An array holds numbers and times, or strings.
  • // line comments and trailing commas are allowed; any other JSON5 syntax is an error.

JSON numbers are read correctly rounded, while the numbers of a text kernel are read as CSPICE reads them, which can be a few ulps off. The same value written in the two formats can therefore give pools that differ in the last bits.
